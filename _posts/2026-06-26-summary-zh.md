## [Un-0：利用耦合振荡器生成图像](https://unconv.ai/blog/introducing-un-0-generating-images-with-coupled-oscillators/) ⭐️ 8.0/10

Un-0 是一款图像生成器，利用模拟的耦合振荡器系统来生成图像，在 ImageNet 64×64 上达到了 6.74 的 FID，与早期领先方法的质量相当。权重、训练和消融代码均已开源。 这项工作展示了一种数字神经网络在图像生成上的可行替代方案，有可能实现更节能的 AI 硬件，并重新激发人们对模拟计算的兴趣。 该系统目前是在数字硬件上模拟的，因此声称的能源优势需要物理实现才能体现。由于 O(n²) 的缩放关系，扩展到 4K 等高分辨率需要数万亿个连接，带来巨大挑战。

hackernews · babelfish · 6月25日 20:50 · [社区讨论](https://news.ycombinator.com/item?id=48679007)

**背景**: 耦合振荡器是物理系统，其中相互作用的振荡器可以协同计算。模拟计算处理连续信号，可能比数字计算更节能。历史上，模拟计算机如 Phillips Machine 曾得到应用，但数字计算后来占据主导。这项研究重新审视用于图像生成的模拟计算。

## [OpenKnowledge：开源 AI 优先笔记应用发布](https://github.com/inkeep/open-knowledge) ⭐️ 6.0/10

OpenKnowledge 作为一款开源所见即所得 Markdown 编辑器发布，支持直接集成 Claude、Codex 等 AI 代理，提供 macOS 应用和 Web UI+CLI 形式。它旨在提供类似 Notion 的写作和分享体验，同时保持数据本地化和隐私性。 OpenKnowledge 填补了 Obsidian（本地 Markdown 和 LLM 支持出色但协作能力弱）与 Notion（协作强大但 AI 和本地文件集成差）之间的空白。它提供了一个本地优先、集成 AI 的解决方案，可能吸引追求隐私与现代 AI 能力的团队和高级用户。 该编辑器基于 Tiptap/ProseMirror 构建，使用 CRDT (yjs) 实现实时协作，并内置 MCP、技能和 RAG 以支持 AI 工作流。但目前仅支持 macOS，不支持本地 LLM，且缺少 Android 应用。

hackernews · engomez · 6月25日 16:04 · [社区讨论](https://news.ycombinator.com/item?id=48675435)

**背景**: Obsidian 和 Notion 是流行的笔记工具。Obsidian 使用本地 Markdown 文件并拥有插件生态，非常适合 LLM 集成，但缺乏原生实时协作。Notion 基于云端，协作功能强大，但使用专有块格式，对 LLM 或本地文件编辑不友好。所见即所得的 Markdown 编辑器允许用户在编辑纯文本时看到格式化内容，AI 集成则使代理能直接在编辑器中读写内容。

## [Simon Willison 将浏览器兼容数据转换为 SQLite 数据库](https://simonwillison.net/2026/Jun/24/browser-compat-db/#atom-everything) ⭐️ 6.0/10

Simon Willison 发布了一个新的 GitHub 仓库 simonw/browser-compat-db，其中包含一个约 66MB 的 SQLite 数据库，存储了 Mozilla 的浏览器兼容性数据。该数据库由 AI 脚本生成，并托管在支持开放 CORS 头的位置，可通过 Datasette Lite 直接访问。 这使得全面的浏览器兼容性数据可以通过 SQL 轻松查询，降低了 Web 开发人员分析跨浏览器功能支持的障碍，无需解析 JSON 或使用 MDN 的 API。 构建过程使用了由 Claude Code for web (Opus 4.8) 生成的脚本，以及由 Codex Desktop (GPT-5.5) 创建的 GitHub Actions 工作流，该工作流将数据库强制推送到一个孤立分支，从而通过 GitHub 的 CDN 实现开放的 CORS 头。

rss · Simon Willison · 6月24日 23:59

**背景**: Mozilla 维护着 mdn/browser-compat-data 仓库，其中包含 JSON 格式的浏览器兼容性数据。Simon Willison 的项目使用 sqlite-utils（一个用于操作 SQLite 的 Python CLI 和库）将该数据转换为 SQLite 数据库。生成的数据库旨在通过 Datasette Lite 等基于浏览器的 SQL 查询工具进行交互式查询。

## [LLM 生成的求职申请缺乏个人真实性](https://simonwillison.net/2026/Jun/24/tom-macwright/#atom-everything) ⭐️ 6.0/10

Tom MacWright 注意到越来越多求职申请完全由大语言模型（LLM）生成，包括作品集、GitHub 项目和提交信息，但无法传达任何个人真实性。 这一趋势削弱了招聘流程，使招聘人员无法评估候选人的真实技能、个性或努力，可能导致在线作品集和求职申请的信任危机。 MacWright 指出，这些经过优化、生成式的简历千篇一律且毫无个性，只能说明应聘者使用了特定工具，而非他们是谁或有何主张。

**背景**: 大语言模型（如 GPT-4）能生成类似人类的文本，包括简历、求职信和代码。随着这些工具广泛普及，一些求职者利用它们自动生成申请材料，但这往往导致内容缺乏个人风格和原创性。真实性在招聘中一直备受重视，AI 生成申请的兴起给招聘人员评估真实候选人带来了新挑战。
