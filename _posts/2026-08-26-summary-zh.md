## [Nitter 和 XCancel 遭停止函威胁](https://github.com/zedeus/nitter/issues/1442) ⭐️ 8.0/10

## [EVE Online 启动从 Python 2 到 Python 3 的迁移](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/) ⭐️ 8.0/10

EVE Online 宣布开始从 Stackless Python 2.7 向 Python 3 迁移，使用 futurize 脚本处理 240 万行代码。随后将人工审查约 2 万个 Python 2 与 Python 3 行为存在差异的位置。 这是一个极具现实意义的案例，展示了如何迁移一个已运行超过 20 年的大型 Python 代码库。其迁移过程对维护遗留系统的开发人员以及计划进行类似 Python 3 升级的团队都具有重要参考价值。 EVE Online 自 2003 年起一直运行在 Stackless Python 上，最后一次重大升级是 2010 年的 Stackless Python 2.7。该公告并未说明如何替代 Stackless，但去年团队曾介绍在其新游戏 EVE Frontier 中使用开源的 carbonengine/scheduler 库。

rss · Simon Willison · 8月25日 22:59

**背景**: Stackless Python 是 Python 解释器的一个变体，以使用称为 tasklet 的微线程实现轻量级并发而闻名，避免了对操作系统线程的依赖。futurize 脚本可将 Python 2 代码自动转换为兼容 Python 3 的代码，并通过 __future__ 和 future 包的导入重新启用 Python 2 兼容性。Python 2 与 Python 3 的差异包括除法行为，例如 1 / 2 在 Python 2 中返回 0，而在 Python 3 中返回 0.5。

## [Linux 技巧让可执行文件兼作 SQLite 数据库](https://simonwillison.net/2026/Aug/24/your-executable-is-a-sqlite-database/) ⭐️ 8.0/10

Farid Zakaria 展示了一种 Linux 技术，可以生成一个既有效 SQLite 数据库又是可执行二进制的单一文件。该技巧将 SQLite 文件第 68 字节处的 4 字节 application ID 设为“SELF”，并把 ELF 可执行文件的各个组成部分存储在多张 SQLite 表中，再通过自定义的 self-exec 加载器来运行。 这项技术将两种广泛使用的格式合为一体，为软件打包和在二进制文件中嵌入可查询的结构化数据开辟了新可能。它可能让开发者把可执行文件当作数据库（反之亦然），从而简化分发、检查和工具链。 该方法把文件第 68 字节处的 application ID 设置为 ASCII 值“SELF”（Structured Executable & Linkable Format）。self-exec 解释器（C 源码在 GitHub 上）提取并运行 ELF 各部分；还可以通过 binfmt_misc 配置让它自动被调用，例如向 /proc/sys/fs/binfmt_misc/register 写入 ':self:M:68:SELF::/usr/local/bin/self-exec:'。
